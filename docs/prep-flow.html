YODA Prep Flow

Amadurece uma issue específica através de Study e Document, sem autorizar implementação. Existe para os casos em que o melhor trabalho de hoje é deixar a issue menos nebulosa.

Quando usar

Quando você quer que uma issue fique pronta para execução, mas não quer que ela seja executada agora. Alguns casos típicos: a issue está no backlog para daqui a duas semanas e você tem contexto fresco hoje; ela depende de outra que ainda não terminou; ou você quer ver o escopo fechado antes de decidir se ela entra no sprint.

A diferença mais importante para o Flow normal é a seleção. O Prep Flow trabalha na issue que você indicar explicitamente, ignorando a ordem do backlog. Preparar documentação de forma independente das dependências é permitido — o que não é permitido é implementar.

Você diz

“Entra no YODA Prep Flow para a issue mynick-0042.”

Como difere do Flow

YODA FlowYODA Prep Flow
Seleção Determinística, pela ordem natural e pelas dependências. Explícita: a issue que você indicar.
Fases Study, Document, Implement, Evaluate. Study e Document apenas.
Dependências Bloqueiam a seleção da issue. Não impedem a preparação.
Estado final A issue chega a done. A issue continua to-do, marcada como preparada.

O que acontece depois

Quando a preparação chega ao Document, a issue permanece to-do com a marca de preparada até ali. Isso tem uma consequência prática útil: quando essa issue for selecionada pelo YODA Flow mais adiante, ela começa direto no Implement, sem refazer Study e Document.

O trabalho de preparação não é descartado nem repetido. Ele é reconhecido pelo fluxo normal como já feito.

Preparar não autoriza executar. O Prep Flow deixa a issue pronta; a decisão de implementar continua sendo uma autorização separada, no YODA Flow.
